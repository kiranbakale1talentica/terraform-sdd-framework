# Master Specification: Terraform SDD Framework

> **Framework-level reference for workflow conventions, standards, and lifecycle gates.**
> This is the canonical source of truth for how this starter kit operates.

---

## 1. Purpose

This framework provides a **structured, repeatable, AI-agent-compatible workflow** for designing, generating, validating, and deploying cloud infrastructure with Terraform.

It enforces a gated 6-phase lifecycle that ensures:
- Infrastructure is **specified before it is built**
- Architecture decisions are **documented and reviewed**
- Generated code is **linted, validated, and security-scanned**
- Deployments are **approved and auditable**

This framework is **cloud-provider neutral**. It works with AWS, Azure, GCP, or any other provider supported by Terraform.

## 3. The 6-Phase Gated Lifecycle

Every infrastructure workload in this framework moves through exactly 6 phases. **No phase may be skipped.**

```
┌─────────┐      ┌─────────┐      ┌─────────┐      ┌─────────┐      ┌─────────┐      ┌─────────┐
│  /spec  │ ───> │  /plan  │ ───> │  /build │ ───> │  /test  │ ───> │ /review │ ───> │  /ship  │
└─────────┘      └─────────┘      └─────────┘      └─────────┘      └─────────┘      └─────────┘
  Discovery        Architecture     Terraform        Quality          Security         Deployment
  & Spec           & ADRs           Generation       Gates            & Cost           Readiness
```

### Phase Gate Conditions

| Phase     | Entry Condition                          | Exit Artifact                                   |
|-----------|------------------------------------------|-------------------------------------------------|
| `/spec`   | Engineer describes a workload            | `specs/<service>/<env>/infrastructure-spec.yaml` approved |
| `/plan`   | Approved spec exists                     | `specs/<service>/<env>/architecture.md` + ADRs  |
| `/build`  | Approved plan exists                     | `terraform/` code generated, `fmt` clean        |
| `/test`   | Build complete                           | `fmt` + `validate` + `tflint` + tests pass      |
| `/review` | Tests pass                               | Security scan + cost estimate reviewed          |
| `/ship`   | Review approved                          | `deployment-readiness.md` signed off; applied   |

## 4. Security Baseline (All Projects)

Regardless of cloud provider or workload type, the following security rules apply to all infrastructure generated by this framework:

| Rule | Enforcement |
|------|-------------|
| No hardcoded credentials in any `.tf` or `.tfvars` file | Pre-commit hook + Checkov |
| Encryption at rest enabled on all data stores | Checkov policy |
| Encryption in transit enforced (TLS 1.2+) | Checkov policy |
| All resources tagged with mandatory tags | tflint rule |
| IAM follows least-privilege principle | Code review gate |
| Remote state stored in encrypted, versioned backend | Required in `backend.tf` |
| CI/CD uses short-lived federated credentials (OIDC) | Workflow template |
| Secrets injected via environment, never committed | `.gitignore` + pre-commit |

## 5. Mandatory Resource Tagging

All resources generated by this framework MUST include the following standard tags.
The actual tag keys used may vary per cloud provider (e.g., Azure uses `tags`, GCP uses `labels`).

```hcl
locals {
  common_tags = {
    Project     = var.project
    Environment = var.environment
    ManagedBy   = "terraform"
    Service     = var.service_name
    Owner       = var.owner
    CostCenter  = var.cost_center
  }
}
```

## 7. Terraform Coding Standards

All Terraform code generated within this framework follows these conventions:

### File Layout Per Service/Environment
```
terraform/services/<service>/<env>/
  main.tf          — Module calls only (no inline resources)
  variables.tf     — All inputs with type + description
  outputs.tf       — All outputs with description
  providers.tf     — Provider + version constraints
  backend.tf       — Partial remote state configuration
  locals.tf        — Naming prefix + common tags
  terraform.tfvars — Non-sensitive default values only
```

### Naming Convention
- **Resources:** `<project>-<environment>-<resource-type>-<descriptor>`
- **Modules:** lowercase, hyphen-separated, capability-focused
- **Variables:** `snake_case`
- **Outputs:** `snake_case`, descriptive

### Provider Pinning
```hcl
terraform {
  required_version = ">= 1.6.0, < 2.0.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}
```

## 8. Validation Command Reference

```bash
# Format check
terraform fmt -recursive -check

# Validate (init first)
terraform init -backend=false
terraform validate

# Lint
tflint --recursive

# Unit Tests (if .tftest.hcl exist)
terraform test

# Security scan
checkov -d . --framework terraform
tfsec .

# Cost estimation
infracost breakdown --path .
```
